2. 번지가 바뀌면 — DNS 와 DDNS ② 번지 알림 담당 (DDNS)

이름이 비슷하지만 다른 사람이다. DNS(Domain Name System)는 전화번호부 — 물으면 번지를 알려 준다. DDNS(Dynamic DNS)는 우리 공유기 안의 번지 알림 담당 — 우리 번지가 바뀌면 번호부에 전화해 우리 줄을 고쳐 달라고 한다. 장면 ① → ② → ③ 을 차례로 눌러 보세요.

손님이 쓰는 이름

설명을 돕기 위한 단순한 그림이다. 바뀐 번지 203.0.113.77 은 그림용이다.

실제로는 이렇게 — "알려 준다", "고쳐 달라고 한다"가 뭔지

DNS 가 "번지를 알려 준다" = 이름을 넣으면 IP 한 줄을 돌려준다. 이 PC 에서 직접 물어본 결과(2026-11-19):

> nslookup example.co.kr
Server:   192.168.0.11      ← 물어본 번호부 (사내 번호부)
Name:     example.co.kr   ← 물어본 이름
Address:  203.0.113.24      ← 돌려받은 번지 (외부 IP)

브라우저 주소창에 example.co.kr:28080 을 치면, 브라우저가 몰래 이 질문을 먼저 하고 받은 203.0.113.24 로 접속한다. 명령 프롬프트에서 nslookup 이름 으로 누구나 해 볼 수 있다.

DDNS 가 "고쳐 달라고 한다" = 공유기가 ipTIME 의 DDNS 서버에 "○○.iptime.org 의 IP 는 지금 203.0.113.77 이에요"라는 등록 요청을 인터넷으로 보낸다. ipTIME 은 그 줄을 새 IP 로 바꿔 적는다. 사람은 아무것도 안 한다. 공유기 관리 화면의 특수 기능 → DDNS 설정에 호스트 이름(○○.iptime.org)과 등록 상태가 보이면, 이 담당이 일하고 있는 것이다.

example.co.kr 줄은 이런 등록 요청이 없다 — 도메인을 산 곳의 관리 화면에 사람이 들어가 IP 칸을 손으로 고쳐야 한다.

3. 안쪽 자리 번호는 누가 정하나 ③ 자리 배정 담당 (DHCP)

안내 데스크 표는 손님을 192.168.0.73 자리로 보낸다. 그 자리 번호를 정하는 사람이 자리 배정 담당이다. PC 가 켜질(출근할) 때 자리를 주는데, 자리 명부(수동할당)에 있으면 늘 같은 자리, 없으면 빈 자리 아무거나다.

5. 우리 관제에서는

  • 지도 관제의 해도 서버 주소는 설정 ENC_SERVER_URL 이다. 회사 · 배 안에서는 http://192.168.0.73:2350(자리 번호)로 바로 간다 — 번호를 적었으니 번호부(4절)도 안내 데스크(1절)도 안 거친다. 대신 해도 서버 자리가 바뀌면 끊긴다(3절).
  • 출장지처럼 건물 밖에서는 자리 번호가 안 통하니 http://example.co.kr:28080/ 로 바꿨다.

해도가 안 나오면 이 순서로 의심한다

  1. 172(또는 그 PC)가 인터넷 · 회사망에 붙었나
  2. 회사 번지가 바뀌었나 — example.co.kr 줄이 옛 번지? → 2절
  3. 안내 데스크 표에 28080 이 살아 있나 → 1절
  4. 해도 서버가 아직 .73 자리인가 — 자리 명부에 있나 → 3절
  5. 해도 서버 프로그램이 켜져 있나

6. 몸으로 해 보기

택배 기사가 되어 본다. "우리 회사" 라는 이름만 받으면 주소록(번호부)에서 번지를 찾고, 건물 정문에서 "28080번 창구요" 하면 안내 데스크가 "해도실 .73 자리 2350호로 가세요" 하고 보낸다. 주소록이 옛 번지면 빈 터에서 헛걸음, 해도실이 다른 자리로 옮겼는데 안내 데스크 표를 안 고쳤으면 빈 자리에서 헛걸음이다.

확인할 것 — 그림에 넣었지만 아직 다 확인하지 못한 것
  • example.co.kr → 203.0.113.24 와, 그 주소의 :28080 으로 해도 그림이 오는 것은 2026-11-19 에 확인했다(이 PC · 172). 공유기 첫 화면의 외부 IP 도 203.0.113.24 로 같았다.
  • ○○.iptime.org 의 실제 이름, example.co.kr 의 DNS 를 누가 관리하는지는 모른다. 우리 공유기의 DDNS 설정 화면은 아직 직접 보지 않았다 — 등록 요청을 어떤 방식으로 보내는지도 ipTIME 이 밝히지 않아 그림은 단순화했다.
  • 자리 명부의 .73 줄(이 PC MAC)은 공유기 화면에서 확인했다. .49 줄이 센서 서버 PC 라는 것은 번호가 같아서 짐작했다. 명부를 누가 넣었는지는 공유기에 남지 않는다.
  • 사내 번호부 192.168.0.11 이 어떤 기계인지 모른다. KT 로 넘어가는 것은 .11 이 대답하지 않을 때다("그런 이름 없음"이라고 대답하면 넘어가지 않는다 — Windows 기본 동작).
  • 회사 · 택배 비유는 이해를 돕기 위한 것이다.
