단계

설명을 돕기 위한 단순한 그림이다. 번호(192.168.0.10 · .11 · 169.254.37.12)는 그림용. 옛날엔 컴퓨터끼리 바로 이을 때 "크로스 케이블"이 따로 필요했지만, 요즘 랜 구멍은 알아서 맞춰 보통 랜선이면 된다.

IP 주소는 누가 주나?

방법은 둘 — 공유기가 나눠 주거나, 사람이 직접 적거나. 그 사이에 "예약"이 있고, 아무도 안 주면 임시 번호가 붙는다.

DHCP = Dynamic Host Configuration Protocol

Dynamic동적 = 그때그때 자동으로
Host네트워크에 붙은 기계 (폰 · PC · 서버)
Configuration설정 (IP 번호 등)
Protocol약속

→ "켜진 기계에 번호 설정을 그때그때 자동으로 나눠 주는 약속". 공유기 안에서 이 일을 하는 게 DHCP 서버 = 그림의 "자리 배정 담당". 사람이 직접 적는 건 반대로 고정(Static) IP.

누가 주나

설명을 돕기 위한 단순한 그림이다. 폰 .5 · 노트북 .20 은 그림용, 해도 서버 192.168.0.73 은 실제 값. 공유기가 나눠 주는 일을 DHCP 라 한다(01 ③ 자리 배정 담당).

일곱 계단 — 집에 기계가 늘어날 때마다

아래 일곱 장은 집에 기계가 늘어날 때마다 생기는 불편 하나와 그걸 푼 것 하나다. 그림마다 😣 불편 → ✅ 해결을 눌러 보세요.

설명을 돕기 위한 단순한 그림이다. 그림 속 번호(192.168.0.○ 끝자리 · 창구 번호 · naver.com 주소)는 그림용이다. 외부 IP · 도메인 · 바깥 창구 번호는 공개용 예시 값, 해도 서버 안쪽 주소(192.168.0.73:2350)는 실제 값.

막혔을 때 묻는 순서

  1. 🛣 길이 닿나? — 선이 꽂혔나, 랜 구멍 불이 켜졌나, 벽 선이 WAN 에 꽂혔나, 모뎀(LTE · 스타링크)이 살아 있나.
  2. 🏷 주소가 맞나? — IP · 이름 · 창구 번호가 맞나.
  3. ✉ 말이 맞나? — 그 창구가 기대한 약속으로 대답하나.

길부터 본다 — 길이 안 닿으면 주소 · 말은 볼 것도 없다. 군산에서 해도가 안 나오면: 172 가 인터넷까지 닿나 → example.co.kr:28080 이 맞나 → 해도 서버가 그림을 주나.
